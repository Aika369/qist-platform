# DECISIONS

Записываем только решения, которые дорого менять позже.

| # | Решение | Причина | Дата |
|---|---|---|---|
| D-01 | Публичное меню — 4 пункта: Home, Opportunities, Researchers, About QIST | Семь пунктов смешивали объекты (Map, Opportunity) и аудитории (Industry, University). Пользователь не должен выбирать между «ищу учёного» и «я из университета» | 2026-09-18 |
| D-02 | «For organizations» в меню пока нет | Сам же рекомендовал делать страницы для продаж после 10–15 интервью с университетами, а не до. Добавить в итерации 3 | 2026-09-18 |
| D-03 | Карта и глобус — виды внутри Researchers, не разделы | Один набор данных не может быть двумя разделами меню, иначе фильтры расходятся | 2026-09-18 |
| D-04 | Matching убран из публичного меню | Подбор персонален; незалогиненный видит пустую форму. Вернётся как «My matches» за входом | 2026-09-18 |
| D-05 | Один тип-перечисление `type` вместо отдельных таблиц для грантов, вакансий и R&D-задач | R&D-задача компании — это `type=rnd_challenge`. Отдельные сущности означали бы тройное дублирование экранов | 2026-09-18 |
| D-06 | Вердикт eligibility берётся из таблицы, а не вычисляется моделью | 13 из 57 респондентов сказали, что им нужны доказательства работы подбора. Таблица воспроизводима и имеет версию источника | 2026-09-18 |
| D-07 | Никаких процентов совпадения | Веса, подобранные без данных об откликах, — выдумка с видом математики. Появятся после калибровки на `match_event` | 2026-09-18 |
| D-08 | Кнопка «Интересно» отключается, если не задан `INTEREST_ENDPOINT` | Правило «кнопка должна выполнять заявленное действие». Лучше честно показать, что приём не настроен, чем писать в localStorage и терять отклики | 2026-09-18 |
| D-09 | 3 из 13 постов не стали возможностями (p9, p12, p13) | Это обсуждения сообщества, а не возможности. Остаются в channels.html, ссылка из about.html | 2026-09-18 |
| D-10 | Дедлайны не переписывались | У o-p3, o-p6, o-p7 дата уже прошла. Придумать новую = сфабриковать данные. Показываем как истёкшие | 2026-09-18 |
| D-11 | Зашитые учётные данные удалены; вход и админка отключаются без бэкенда | `admin@qist.kz / qist-admin-2026` лежали в публичном JS — любой посетитель входил в админку. Регистрация писала аккаунт в localStorage посетителя, то есть до нас не доходила | 2026-09-18 |
| D-12 | Координаты не геокодировались; вместо этого добавлено поле `geo_precision` | 338 из 497 записей имеют координату центра страны, у 214 нет даже организации, геокодер недоступен. Придумать координаты = сфабриковать данные. Показываем страновую метку с подписью «город не указан» | 2026-09-18 |
| D-13 | Кластер считается страновым, если город известен меньше чем у половины | Первое правило («хотя бы у одного есть город») помечало 99 записей в Астане как точный адрес из-за одного человека | 2026-09-18 |
| D-14 | Дубликаты помечаются полем `possible_duplicate_of`, но не удаляются | Правило «не удалять пользовательские данные ради удобства реализации». Решение принимает человек | 2026-09-18 |
